# Compact AI query output

UO.Graphs 0.12 adds **opt-in compact query v1**. Default standard query/status v6,
index/doctor v4, SQLite v3 and declaration identity v2 remain compatible. No
re-index is required for a schema-3 snapshot. This is an output/selection revision,
not a new extractor, service, runtime dependency or release acceptance claim.

## Root cause, verified from code and actual output

`GraphQueries.Neighbors` orders adjacency by relationship ID; BFS applies result
limits in that discovery order. IDs are hashes, not semantic-importance ranks.
`ReadOutputWriter.Query` removes optional metadata first, then whole result tails.
Thus an early property getter/setter can survive both limits while later ordinary
calls disappear. `--limit 10` cannot fix the character cost of its first results.

`QueryItem` embeds both `RelationshipSymbol` and `GraphEntity`. Every `QueryStep`
embeds the entire relationship (including source/target symbols) and occurrence
array. Every occurrence repeats snapshot/context, file/hash, reasoning and bound
signature. These are useful rich records but costly when nested repeatedly in a
workflow answer. The original v6 standard view retains this shape for consumers.

On the existing IslemKaydi snapshot `003729cdc2294eb88cf5da2d8b67b651`, a 12,000
budget again returned only `Entity.Id.get` and
`TreatmentPlanItem.TreatmentTypeCodeSnapshot.set`: **9,930 characters, two edges,
three occurrences, zero non-property calls**. A large bound exposed all 40 targets,
26 property-accessor targets and 48 returned occurrences. Source inspection of
`AddTreatmentPlanItemHandler.HandleAsync` confirmed the seven specified calls;
they are not generated by a name/importance heuristic. Same-snapshot comparison
below reproduces the observed 163,698-character size at a 200,000 budget; using a
1,000,000 budget adds one serialized character in the budget field (163,699).

`DeliveryWriter.Context` previously discarded snippet text before nearby nodes
and relationships. A successful file hash check could therefore coexist with
`text: null`. With an explicit `--include-source`, optional nearby/relationship
records now go first. Text can still be removed if the remaining envelope cannot
fit; source/hash status is never rewritten to imply freshness. A depth-0 context
or direct authorized source read is useful for a focused excerpt.

## Wire contract and selection

```sh
uographs query callees 'SYMBOL_ID' --view compact --calls exclude-properties --depth 1 --limit 100 --max-edges 500 --evidence-limit 2 --max-chars 12000 --db 'DB'
uographs query callees 'SYMBOL_ID' --view compact --calls only-properties --depth 1 --limit 100 --max-edges 500 --evidence-limit 2 --max-chars 12000 --db 'DB'
uographs query dependencies 'MESSAGE_ID' --view compact --direction incoming --edge-types HANDLES,DISPATCHES --evidence-limit 2 --max-chars 12000 --db 'DB'
```

The envelope declares `view: compact`, `compactVersion: 1`, `baseQueryVersion: 6`;
it deliberately has no `schemaVersion`, so a v6-only parser cannot silently read
integer references as embedded objects. Updated consumers: envelope schema checker,
skill real-subprocess validator, all five distributed skill/reference copies.
Existing standard consumers and export/context formats retain their contracts.

| Table/field | Meaning |
| --- | --- |
| `symbols` | Full ID and display signature once; assembly/project references; entity kind/confidence/sources when loaded; optional framework declarations preserved |
| `items[].symbol`, `resolvedStart`, `resolvedTarget` | Zero-based symbol index, or null; ambiguity remains unresolved selection even with one displayed candidate |
| `items[].path[]` | Relationship index plus `reversed`; follow source→target or target→source from the selected root |
| `relationships` | Full ID, kind, symbol endpoints, context project reference, confidence, callKind, evidence indices, evidenceTotal and evidenceTruncated |
| `evidence` | Full occurrence ID, exact source range, reason/boundTarget text indices, related symbol indices; snapshot inherited from envelope and context from relationship unless an explicit project override exists |
| `files` | Exact file path, SHA-256, generated flag; source `file` indexes this table |
| source `range` | `[startLine,startColumn,endLine,endColumn]`, one-based original values |
| `texts`, `assemblies`, `projects` | Interned exact strings; project scope remains in analysisContext |
| `selection` | Selection unit, eligible, filtered, beforePage, collected, returned, omittedByBudget, remaining, grouped and continuation |

IDs are never truncated. Array references are local to a single output document;
join pages by full IDs, never by array index. There is no symbol/entity pair to
reconcile in compact output. `hasEntity` distinguishes known declarations from
external endpoints; `kind: null` and empty sources can mean declaration detail was
not loaded for that endpoint. Fetch `query symbol ID` when required.

Optional fields listed in `omittedSymbolFields` are canonicalIdentity, parentId,
documentationId, declarationId, name and qualifiedName; standard `query symbol`
recovers them. The full display signature and stable ID remain. Full assembly
identities are interned rather than shortened. Framework metadata, reasons, bound
signatures, related candidates, evidence ranges and hashes remain exact. Compact
`--details full` restores full analysis metadata, not omitted symbol fields.

All queries support compact projection. For **depth-1 callees/callers/dependencies**,
it also selects individual relationships (including unresolved observations),
instead of one discovered path per reachable symbol. Multiple kinds/confidences
between endpoints are therefore visible. Default confidence policy is exact plus
unresolved observations; inferred remains explicitly opt-in. For other queries,
standard BFS/find/ambiguity semantics remain and unresolved targets are not
traversed. This difference is declared in `selection` and the CLI help.

`--calls` is only accepted with compact one-hop queries. `all` is the default;
`exclude-properties` excludes only CALLS whose **stored identity-v2 declaration
key** begins `accessor:` and ends `:PropertyGet` or `:PropertySet`. These tags are
emitted from Roslyn `IMethodSymbol.AssociatedSymbol/MethodKind` in
`SymbolCollector.DeclarationKey`, including metadata accessors. No method-name
similarity, regex inference, business rank or new call edge is introduced.
`only-properties` is the complementary explicit inspection. Custom getter/setter
bodies are included in this filter too; no accessor is silently judged trivial.
Other calls (constructors, event accessors) and non-CALLS edges remain with
exclude-properties. `callKind` is propertyAccessor, otherCall, unresolved, or null
for non-CALLS. There is **no grouping** (`grouped: 0`).

Ordering is ordinal relationship ID, deterministic within a snapshot and query
policy, not importance or runtime execution order. Filtering occurs before the
result limit and character budget. Counts describe the root, direction, edge-kind
and confidence selection; they are not whole-graph completeness claims. Count
SQL scans the matching adjacency. `max-edges` limits materialized edge records,
not aggregate count-scan cost. Full-table/workload performance is not claimed.

On truncation, narrow exact endpoints, direction or edge types, or use the returned
`selection.continuation` with the same query:

```sh
uographs query callees 'SYMBOL_ID' --view compact --calls exclude-properties --depth 1 --limit 100 --max-edges 500 --evidence-limit 2 --max-chars 12000 --after 'CURSOR' --snapshot 'SNAPSHOT_ID' --db 'DB'
```

The cursor binds snapshot, resolved root, command, direction, normalized edge types,
confidence policy and call filter. Policy/snapshot mismatch and an absent cursor
edge fail with exit 2. Page size, evidence limit and character budget may change.
The consistency hash is not a security/authorization mechanism. No cross-snapshot
or multi-hop continuation is promised. A whole indivisible record larger than the
budget still gives exit 2 and a measured minimum; inspect a narrower source/symbol
before increasing the bound. Never silently choose an ambiguous name.

Budget measurement serializes the **final compact document** and includes exactly
one final LF in Unicode scalars. Whole items/paths and their referenced records are
re-projected after pruning, so no dangling references or sliced JSON are produced.
Metadata pruning remains independent and reported by `metadataSummary.fields`.
`evidenceTruncated` and `evidenceTotal` report occurrence limits (the total is null
for non-paged queries where it was not counted). Coverage/freshness flags, scope,
query diagnostics, outcome, uncertainty and source evidence remain available.

## Controlled same-snapshot measurements

macOS ARM64, SDK 10.0.201/runtime 10.0.5. Three sequential CLI processes per row.
Wall-clock timer includes process startup, SQLite query, projection/serialization
and stdout/stderr collection. Caches were not flushed, scenario order was fixed,
and concurrent load was uncontrolled. No tokenizer/model token measurement, memory
measurement, AI comparison or general speed/savings claim was made.

Both representations use depth 1, limit 100, max-edges 500, evidence-limit 2.
Small budget = 12,000, large = 1,000,000 scalars including LF. This compares the
unchanged standard v6 representation to compact v1 in the same 0.12 executable,
not two independently built historical executables. The explicit property filter
changes selection and is reported separately from representation-only compression.

The [fixture source](../tests/Fixtures/AiWorkflow.cs.txt) is copied into the prepared
Phase2 Library fixture with its assets and global.json; no restore or generators.

163 entities / 403 relationships / 516 occurrences. Run has 69 direct CALLS:
62 property accesses including custom bodies, and seven predefined critical calls.
[Actual complete compact workflow stdout](examples/compact-workflow.json) is
byte-for-byte CLI output, including its final LF, not a hand-authored mock.

## Skill and remaining limits

Five identical skills now prefer `rg` for simple lookup, a short source/test read
for workflow understanding, graph queries for uncertain semantic links, compact
one-hop calls and HANDLES/DISPATCHES for mediator links. They do not mandate a
command chain, automatically enlarge budgets or mistake selected hash matches
for global freshness. Reports scale to task size while retaining material limits.
Plugin version is 0.4.0; installed plugin caches are not changed.

No custom accessor is classified as unimportant; exclusion is explicit. No
source-order/runtime-order assertion or business-ranking heuristic exists.
Canonical/parent/name detail is optional through standard symbol reads; complete
assembly identities and all returned occurrence fields remain available. Full
metadata still has no size cap when explicitly requested. Multi-hop queries retain
one-path-per-symbol semantics and have no continuation token. Large adjacency
count cost and compact projection at extreme limits remain unbenchmarked.
